Today's Mission
Use place value to compare two multi-digit numbers — and order a list of them from least to greatest. Read left to right. The first place where the digits disagree is the place that decides.
❓
Essential Question
When two big numbers look almost the same, how do you decide which is bigger?

Last lesson asked: when a number grows, which digit changes? Today asks the next question: when two numbers differ, which place tells you which one is bigger?

Place value answers both. You don't have to compare every digit — you just have to find the first one that argues.

📐 What You Just Saw

Walk left to right. Stop at the first argument.

When two numbers have the same number of digits, line them up by place. Compare the leftmost digits first. If they match, move right. The first place where the digits differ is the place that decides — the bigger digit there means the bigger number, no matter what comes after.

If the digits all match? The numbers are equal.

🔗 When Felix's Shortcut Works (and When It Doesn't)

Felix said: "Count the digits first. If one has more digits, it's bigger." Let's see when that's enough — and when it isn't.

Pair Felix's Shortcut Does it work?
98,750  vs  102,000 5 digits vs 6 digits ✅ Yes — 102,000 is bigger
487,290  vs  478,920 6 digits vs 6 digits ⚠️ Tie — need to walk left to right
9,999  vs  10,000 4 digits vs 5 digits ✅ Yes — 10,000 is bigger
63,402  vs  63,420 5 digits vs 5 digits ⚠️ Tie — need to walk left to right

The rule: If the digit counts differ, Felix wins — more digits means a bigger number. If the counts match, you need Atlas's chart-stack. Walk left to right and find the first arguing place.

Worked Example: Order Four Stadiums
From least to greatest. Same rule, four numbers at once.
Problem

Four Florida college teams reported total season attendance: 647,210 · 64,720 · 647,120 · 648,000. Put them in order from least to greatest.

Watch the Math Crew work it out:

F
Felix — count digits first
"64,720 only has five digits. The other three have six. So 64,720 is the smallest. Park it at the start."
A
Atlas — stack the rest
"Now I have three six-digit numbers. I stack them lined up by place: 647,210 / 647,120 / 648,000. Hundred-thousands: all 6. Ten-thousands: all 4. Thousands: 7, 7, 8."

64,720 < 647,120 < 647,210 < 648,000

H
Hazel — find the arguments
"648,000 has 8 in thousands — biggest of the three. Park it at the end. Now between 647,210 and 647,120, the first argument is in hundreds: 2 vs 1. 2 wins, so 647,210 is bigger."
C
Cora — verify the chain
"64,720 < 647,120 < 647,210 < 648,000. I check by reading the chain left to right: each < symbol opens toward the bigger number. The chain holds."
💡

Strategy: When you have to order a list, use Felix's shortcut first to peel off any obvious outliers (numbers with fewer digits). Then use Atlas's stack and Hazel's argument-finder on what's left. Cora always checks the final chain.

⚖️
Chart-Walk vs Reading Aloud
Two strategies for the same comparison.

Two students compared 320,540 and 325,040. Each used a different strategy.

STUDENT A — Chart-Walk
"I stack them by place:
3 2 0, 5 4 0
3 2 5, 0 4 0
Hundred-thousands 3 = 3. Ten-thousands 2 = 2. Thousands 0 vs 5. First argument! 5 wins, so 325,040 is bigger."
STUDENT B — Read Aloud
"320,540 reads 'three hundred twenty thousand, five hundred forty.' 325,040 reads 'three hundred twenty-FIVE thousand, forty.' Both start with three hundred twenty thousand — but the second number keeps going with 'five thousand.' So 325,040 wins."
🧐

Both students get the same answer: 325,040 > 320,540. Student A walks the chart. Student B uses how the numbers sound when read aloud. Both are real strategies — and they're really the same idea told two ways.
